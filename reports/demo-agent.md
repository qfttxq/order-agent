# 需求评估：Agent / 工作流自动化

> **可以接，但先做一轮澄清。** 把范围压死再谈价，不要现在给确定数字。

## 一、判定

| 项目 | 结果 |
|---|---|
| 类型 | Agent / 工作流自动化 |
| 置信度 | 95% |
| 匹配度 | 中，可接但要控制范围 |

**判定依据**（引号内为客户原话）

- 有流程自动化诉求：「…ERP，两个人每天花两小时，想自动化」
- 要求系统对接：「另外还要顺便对接一下企业微信通知」
- systems：「提到系统：抖店、ERP、企业微信」

**风险点**

- 出现「顺便/还要」等扩范围表述，必须在一期范围里明确写死

## 二、问客户的问题（15 条）

> 以下可直接复制发给客户。已经说过的内容不重复问，只问缺失的关键项。

### 流程边界

1. 请把这个流程从头到尾走一遍：谁发起、经过哪几步、到哪一步算结束？
   <sub>为什么问：A 类的范围就是流程条数，流程说不清就没法定价，也没法验收</sub>
2. 现在这套流程每天/每月跑多少次？每次大概花多少人工时间？
   <sub>为什么问：频次和人工时长决定这单对客户值多少钱，也决定你该报多少</sub>
3. 有没有例外情况——比如数据不全、审批被驳回时，现在是怎么处理的？（可不答）
   <sub>为什么问：例外分支通常占总工作量的一半，客户往往想不起来说</sub>

### 系统与接口

1. 要读写哪些系统？这些系统有没有开放 API 或者能导出数据？
   <sub>为什么问：没有 API 就只能退化成模拟点击或人工中转，性质和报价都变了</sub>
2. 系统是自建的还是采购的？如果是采购的，能不能找厂商开接口？（可不答）
   <sub>为什么问：采购系统开接口要走厂商流程，可能拖一个月</sub>

### 授权范围

1. Agent 能不能直接执行写操作（下单、改状态、发消息），还是只能给建议由人确认？
   <sub>为什么问：写权限越大，出错代价越大，责任划分必须在合同里写清</sub>
2. 操作日志需要留多久？出问题时要能查到哪一步吗？（可不答）
   <sub>为什么问：可追溯是生产级和 Demo 的分界线，也是你和低价竞争者的差别</sub>

### 异常与责任

1. 如果 Agent 判断错了、造成了实际损失，责任怎么算？希望怎么处理？
   <sub>为什么问：A 类最高频的争议点，开工前不谈清楚，验收时一定扯皮</sub>
2. 出错时需要人接管吗？接管的人希望看到什么信息？（可不答）
   <sub>为什么问：人工接管界面是必做项还是可选项，差一到两周工作量</sub>

### 效果定义

1. 怎么算这个 Agent 做成了？是「跑通一次」，还是「连续两周不出错」？
   <sub>为什么问：效果定义不同，验收周期差好几倍，必须此刻定下来</sub>
2. 能接受的成功率是多少？（比如 100 单里允许几单要人工介入）
   <sub>为什么问：任何 A 类都有失败率，承诺 100% 等于无限责任</sub>

### 数据合规

1. 流程里会碰到客户个人信息、支付或合同数据吗？（可不答）
   <sub>为什么问：涉及个人信息就要考虑脱敏和留存，可能影响方案选型</sub>
2. 数据能不能离开你们内网？（可不答）
   <sub>为什么问：决定能否用云端模型，直接改变成本和可行性</sub>

### 风险与边界

1. 你提到的这些里，哪一件是最要紧、必须先上线的？
   <sub>为什么问：扩范围表述必须先排序，否则一期永远做不完</sub>
2. 这个项目的预算区间大概是多少？
   <sub>为什么问：预算决定方案档位——同一件事，5 千和 5 万的做法完全不同</sub>

## 三、报价建议

| 档位 | 报价 | 周期 |
|---|---|---|
| 单流程 PoC | ¥6,000 – ¥15,000 | 14 天 |
| 单流程生产版 | ¥35,000 – ¥60,000 | 30 天 |
| 多系统 Agent | ¥80,000 – ¥250,000 | 60 天 |
| 按月维护 | ¥15,000 – ¥25,000 | 每月 |

**单流程 PoC** — 含：一条主流程端到端跑通；10 条真实样本测试，给出成功率；一页结论：能不能做、卡在哪、生产化还要多少

不含：不接生产系统，用测试数据或只读权限；不含异常处理与人工接管界面；不含部署与运维

**单流程生产版** — 含：主流程 + 异常分支的完整实现；失败重试、幂等、断点续跑；人工接管入口与操作日志；连续 100 次执行的稳定性验收

不含：不含上游系统改造（需对方配合的部分由客户协调）；不含新增流程，超出按每条 ¥8,000–20,000 另计

**多系统 Agent** — 含：多流程编排与统一状态管理；跨系统数据一致性与补偿机制；可观测：执行链路追踪、成功率看板、告警；权限分级与审计日志

不含：不含客户侧系统接口开发；不含长期运维

**按月维护** — 含：每月固定巡检与问题修复；上游系统变更后的适配；新增 1–2 条轻量流程；月度运行报告（成功率、人工介入率、节省工时）

不含：不含重写或架构级改造

**报价依据**

- 按系统对接数量估算：3 个系统
- 3 个系统，属多系统 Agent，需做统一状态机、跨系统补偿与可观测

**付款方式**

- 签约预付 30%，PoC / 阶段交付后 30%，验收通过后付 40%
- 诊断版一次付清
- 个人账户收款，双方签署书面服务协议并出具收款收据
- 变更需求需书面确认，按增减量调整预算与周期

> 到手参考：平台单扣 11.4%（服务费 5% + 税费 6.36%），最高档 ¥250,000 实收约 ¥221,500；私单不扣，但需自行承担协议与收据。

## 四、验收单草稿

> 每一条都能由一个第三方独立判断通过与否。模糊表述一律不写进验收单。

| 验收项 | 判定标准 |
|---|---|
| 主流程跑通 | 双方确认的每条流程，在真实或等同真实的环境中端到端跑通一次，从触发到结束状态正确（涉及系统：抖店、ERP、企业微信） |
| 运行成功率 | 连续执行 100 次，成功完成 ≥ 95 次。「失败」不含上游系统不可用、账号权限失效、源数据本身缺失这三种情况 |
| 异常正确停止 | 准备 10 个异常场景（数据缺失、接口超时、权限不足、状态冲突等），其中 ≥ 9 个能被正确识别并停止，且发出通知，不产生错误写入 |
| 执行可追溯 | 每次执行可查到：触发时间、每步决策依据、调用结果、最终状态；任取 10 次执行记录，信息完整 |
| 人工接管 | 出现异常时可人工介入并继续处理；接管后流程状态正确，不发生重复写入 |

**不包含**

- 上游系统的改造、接口开发由客户方协调，不在本次范围
- 上游系统自身故障导致的失败不计入成功率
- 约定的流程条数之外的新增流程，属新增范围
- 客户内部操作规范变化导致的效果下降，需另行评估
- 不含 7×24 值守与故障即时响应

**交付物**

- 可运行的 Agent 与完整配置
- 部署文档与运行手册
- 异常处理与人工接管操作说明
- 测试样本集与成功率测试报告
- 一次 60 分钟的线上培训与录屏
